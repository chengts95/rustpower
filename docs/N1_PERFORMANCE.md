# 完整 N−1 首轮性能结果

实验路径：固定分区、共享 DC/AC 符号、主线程逐组发射 patch、worker DCPF+Newton、
共享支路数据后处理与触发输出。没有 Q-limit 和 Slack 可达性预检查。旧单 App
重建路径未作为本轮性能参照，本轮评估新路径的 1→2→4 worker 并行扩展。

## 实验配置和计时边界

- release opt-level=3，普通默认编译参数，系统动态 KLU。
- Intel Core Ultra 7 288V，整个进程限制在 CPU 0–3（四个高频核）；线程在这组核内
  调度，每个线程未单独固定 CPU。依次 1、2、4 worker，各跑一个完整批次。
- batch_size=8，max_iter=50，tolerance=1e-10。输入为各案例全部在役线路和两绕组
  变压器，每项独立退出一个完整设备，包含数值失败场景。
- 所有支路配置加载率 >100% 规则，另加一个显式求解失败规则。worker 计算、规则
  检查、MPSC 传输及收集者提取紧凑统计均在整批时钟内。计时内没有逐事件打印。
- `prepare_n1` 从已有初始化主 World 开始，包含共享模式、J 元数据、两套符号分析、
  目录及 WatchPlan 准备。输入加载和主 World 初始化另列。
- 整批时钟从调用 `run_n1` 前开始，到该函数返回后结束，包含 worker/App 创建、
  描述符生成、数值 patch、DCPF、NR、后处理/触发、队列和收集者结束/join。
- 事件记录的排序和 JSON 文件落盘在整批时钟外。共享准备只做一次，各 worker
  配置复用同一个 PreparedN1。

## 按总迭代数估算

单 worker 得到两个不同口径：

- 纯 AC 迭代区间平均：1.918564 ms/尝试。
- 整条流水线摊销：2.215726 ms/尝试。

使用后者按用户提出的办法估计同配置的等价串行成本：

```text
τ = T_run_1 / AC_attempts_1
T_equivalent_serial_P = AC_attempts_P × τ
S_estimated_P = T_equivalent_serial_P / T_run_P
E_estimated_P = S_estimated_P / P
```

这是同一基准、规则和场景组合下的工作量归一化估算。DC、初始 AC 检查、失败、
后处理和线程启动成本被摊入 τ；因此同时提供实际 T_run_1/T_run_P 和阶段计时。

## 阶段累计时间

这些是各 worker 用 Instant 测量的阶段墙钟之和，包含该区间内的调度停顿。
各 worker 区间重叠，不能把累计值当作整批耗时或线程 CPU 时间。

| Worker | DC 累计 s | AC 累计 s | 其中 AC 迭代 s | patch 累计 s | 后处理/规则累计 s |
|---:|---:|---:|---:|---:|---:|
| 1 | 11.008 | 184.791 | 178.398 | 0.009199 | 9.687 |
| 2 | 11.293 | 191.286 | 184.733 | 0.006798 | 9.790 |
| 4 | 12.897 | 232.072 | 224.381 | 0.007541 | 11.336 |

DC 时钟仅包围 KLU DC 数值调用。AC 从 DC 成功后构造初值开始，结束于返回前、
输出电压 clone 之前；AC 迭代是 J 数值填充、线性求解、电压更新和 mismatch。
线性失败也记录一次尝试和实际花费。patch 为固定槽回填/覆盖；规则时钟包含目标
后处理及命中生成，外部发送/收集包含在整批时钟中。

4-worker 的累计 AC 迭代区间比单 worker 增长约 25.8%；效率损失主要体现在这些
数值区间内。当前测量尚未区分频率、调度及访存的贡献。patch 只有毫秒级累计成本。
