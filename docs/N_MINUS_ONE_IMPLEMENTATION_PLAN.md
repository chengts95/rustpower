### 实际线程模型

```text
主线程：遍历候选 → 桥边分类（benchmark 编排）→ 编译 patch → 任务组队列
                                                             ↓
                    四个 worker：领批 → patch/NR → 后处理/规则 → 结果组队列
                                                                          ↓
                                                                  独立 collector 回调
```

每次 run_n1 创建四条 worker 线程和一条 collector 线程，调用线程负责发射。
每个 worker 在线程内部创建自己的 App、Numeric/Common 与数值缓冲，并一直
处理到该次调用结束。主系统通过 scoped thread 的 join 保证只读共享存储的
生存期；Bevy Resource 的裸指针桥接集中在 execution.rs 的 Input 封装。

任务和结果队列底层均使用 crossbeam_channel 的有界 channel，容量各为 2P。
实际使用方向分别为单生产者/多消费者、多生产者/单消费者。worker 算完一批后
竞争领取下一批；本地持有的整批在同一线程内串行求解和后处理。当前每线程
本地待取任务双端队列数量为零。批大小默认 8、硬上限 32；四 worker 时，队列、
worker 与生产端至多持有约 `(2P+P+1)B = 104` 个任务描述符。

空队列时先 yield，持续空闲后 sleep 50μs；生产者发完后设置 done 并关闭输入。
worker 排空任务并退出，collector 在全部结果发送者释放后结束，最后统一 join。
每次下一轮 run_n1 都重新创建线程、App 和 Numeric。当前 n1_retry_dc 是单独的
第二次调用/进程，重新准备该批共享数据，并复用现有队列执行代码。

当前实测：四 worker 的完整筛选批次 29.322 s、平均 3.91 忙核，四个 worker
各约 28.5–28.9 CPU s。主线程采样累计约 0.149 CPU s，collector 约 0.012 CPU s。
后处理和规则检查在 worker 内完成。10 个连通失败场景 DCPF 补测全部成功完成
DC 初始化，AC 都达到 30 次上限；后续 LMPF 结果按同一场景身份关联。

## 目标与已确定边界

主 World 管理原始设备、参数和基准运行状态。一次 N−1 批次由同一基准上的
独立单设备退出场景组成。首版覆盖线路、两绕组变压器整设备退出，关闭 Q-limit，
固定母线映射、PQ/PV/Slack 分区以及 Ybus、DC B、AC J 的结构。

运行前省去从 Slack 出发的全量可达性检查。DC/AC 数值失败或不收敛记录场景失败，
worker 推进进度并继续下一项；按显式状态规则决定是否外发失败数据。首版沿用既有参考母线配置。

原始 World 始终保持基准数据。worker 使用独立计算工作区，无设备实体复制、
无原始数据编辑/撤销事务。旧单 App 求解路径和旧 KLU API 保持现有入口。

## 执行架构

```text
主 World / 批次生产者
  ├─ 持有稳定的共享只读基准、结构、DC/AC Symbolic
  └─ 发射任务组 ───── SPMC ──→ N 个常驻计算线程
                                  每线程内部创建一个 App
                                  组内 DCPF/NR → 规则检测 → 命中后提取
                                             │
收集者 ←──────────────── MPSC ────────────────┘
```

采用固定数量的普通线程，每线程内部创建、运行并销毁自己的 App。App 安装专用
N−1 插件，资源只包括共享基准入口、本地矩阵/向量/分解工作区、任务和结果。
外部队列承担线程间通信，Bevy message 负责 worker 自己 World 内的阶段推进。

任务队列只有主生产者写入，多个 worker 消费；结果队列仅在规则命中时由 worker 写入，一个收集者消费。完成进度单独维护。首版无需 Future、异步 runtime 或通用线程池调度层。

## 共享数据与所有权

主 World 的稳定存储持有：

- 设备参数、基准数值、设备身份到密集计算索引的映射。
- 母线合并及最终 PQ/PV/Slack 置换映射。
- Ybus、B、J 的只读模式数组，J 的分段边界及对角索引。
- DC 和 AC 各一个 KLU Symbolic；同一种符号对象在所有 worker 间共享。
- 批次统一的求解配置和输出选项。

worker 独占：Ybus/B/J 数值、RHS、注入和电压缓冲、DC/AC 各自的 Numeric/Common。
创建 worker 时初始化所需数值缓冲；设备 ECS、结构和符号对象保持共享。

共享入口采用主系统统一管理的只读借用/窄裸指针封装。主系统在所有 worker
退出并 join 后释放共享存储。共享入口的线程契约和 FFI 转换集中在新模块中。

## COO 发射、置换与值槽解析

### 一次性基准准备

1. 先固定密集母线索引、母线合并映射和 PQ/PV/Slack 置换。
2. 设备盖章时直接发射最终求解空间的 COO 坐标和归一化贡献。
3. 压缩、排序、合并重复坐标，形成整个批次固定的 CSC 模式。
4. 预留必要的结构对角和零值位置；场景数值为零时继续保留该位置。
5. 从同一固定模式准备 DC/AC 结构、J 分段信息，并完成各自符号分析。

COO 确定贡献的行列坐标；最终 `values` 偏移由压缩后的 CSC 布局确定。
设备的多个 COO 贡献以及多台并联设备，可以落在同一个 CSC 值槽。

### 场景投递

主线程基于设备的置换后 COO 坐标，解析最终 CSC 值槽，生成本次场景的覆盖描述符。
每个场景在本批次发射一次，首版无需常驻的全设备直接地址缓存。解析可采用最终
列内查找；如果自定义压缩过程能顺带回填 COO→CSC 映射，也可边构造边生成。

主线程生成描述符与 worker 求解重叠执行。首先测量实际生产开销和队列供给情况，
再决定重复 N−1 批次是否值得保留偏移缓存。偏移指 `values` 元素下标，避免在线程间
传递指向某个 worker 缓冲的绝对内存指针。

对两端口支路，将相同值槽的本设备贡献先累加：

```text
outage_value[slot] = baseline_value[slot] - sum(device_contributions_at_slot)
```

保留并联设备、充电和实际端点开关模型的其他贡献。线路、变压器使用当前模型的
完整 2×2 patch 和正确基值；变比/移相两侧分别取对应项。

## 任务与结果协议

每个场景包含固定大小的标识与数值覆盖信息；队列传递包含多个场景的任务组，
避免 worker 再查询 ECS 或解析坐标：

```rust
struct ValuePatch<T, const N: usize> {
    len: usize,
    slots: [usize; N],
    values: [T; N],
}

struct N1Task {
    case_id: usize,
    y_patch: ValuePatch<Complex64, 4>,
    dc_patch: ValuePatch<f64, 4>,
    dc_rhs_patch: ValuePatch<f64, 2>,
}

struct N1TaskBatch {
    tasks: Vec<N1Task>,
}
```

这里是字段草案；DC RHS 的正负号和所覆盖向量在实现中以现有 DCPF 公式定义。
设备种类和外部 ID 来自共享设备映射。场景流按需生成，命中结果携带 case_id 与
退出设备标识，首版避免按总场景数分配完整任务表或完整结果表。一次运行
一个批次，统一配置绑定到执行上下文，省去每条任务重复传送。

结果协议改为稀疏的触发输出。规则命中时才生成 N1TriggeredOutput，包含
case_id、退出设备、rule_id、监测目标索引、触发值和按配置提取的数据。组内命中
结果可批量回传；零命中场景和零命中任务组完全不写结果 MPSC。

完整电压或设备结果通过独占 Vec/Box 转移所有权；worker 后续写入独立工作缓冲。
收集者仅接收、归档、恢复外部设备身份或执行 I/O。数值后处理和规则检测都在 worker。

普通完成、失败、发射事件数量采用独立的批次/worker 计数。数值失败按失败计数；
仅在显式配置了失败触发规则时写结果 MPSC。失败后按需重建本 worker 的 Numeric，
保留共享结构，继续处理同组后续场景。

## worker 的常数次 patch 与阶段执行

worker 维护一份已初始化的本地数值数组，以及前一场景涉及的少量槽位。
领取新场景时，将前一场景涉及的槽位用共享基准值覆盖，再写入当前场景的退出值。
Ybus 至多覆盖前四个槽加当前四个槽，工作量与网络大小无关。保存的是前一任务的
短描述符；基准值始终从共享基准读取，无需逐任务保存旧数值或重复制整张矩阵。

采用绝对覆盖值，避免场景间反复加减造成累计漂移。无 Q-limit、分区固定时，
持续复用 J 模式和 DC/AC Symbolic；每任务从统一基准初值及注入定义自己的数值状态。

阶段顺序：

```text
领取一组任务
→ 组内逐场景：覆盖数值槽 → DCPF → Newton → 保存电压/状态
→ worker 批量计算配置规则所需指标
→ 命中生成本地触发 message
→ worker 按触发配置提取指定结果
→ 有命中才发送结果组
→ 领取下一组
```

### 有硬上限的任务组与流式生产

任务生成器逐组发射描述符，总场景数 M 再大也按固定窗口推进。主系统保留共享
设备数据与当前发射窗口；worker 同时最多持有一个大小不超过 B 的任务组。

首版设可配置的 batch_size_max（初始默认 32，作为待测的工程默认值），以及
worker_batch_bytes_max。由后者推导 B_memory_limit，始终满足：

```text
B_est = max(1, ceil(M / (P * K)))
B = min(B_est, batch_size_max, B_memory_limit)
1 <= B <= batch_size_max
```

batch_size_max 是独立硬上限，M 的增大只增加任务组数量。若单场景工作区和必要
输出已超出配置内存预算，在初始化时报配置错误。尾组只含剩余场景。

SPMC 使用有界任务组队列，容量配置为少量 worker 数的倍数（例如首版 2P）。
这样队列中最多容纳 2P 个组，每个 worker 最多领取一个组；待发描述符规模受
P、B 和队列容量限制。生产端在容量耗尽时按队列协议等待/重试，收集端独立推进。

worker 组内连续复用一套 DC/AC Numeric/Common，逐场景保存电压和状态，再集中
进行指标计算及触发输出。Numeric 内存按 worker 计；批量电压和输出缓冲按 B 计。
Complex64 电压每场景约为 16×母线数 字节，按配置的最大组容量复用缓冲。
若本批规则只读取求解状态，省去完整电压的批量保留。

### 实体上的数据驱动配置

规则由主 World 的设备/母线实体上的类型化组件配置。以下为字段草案：

```rust
struct N1Watch {

    metric: Metric,            // Vm、支路电流/加载率、求解状态等
    predicate: Predicate,      // 小于、大于、区间外、失败阶段等
    emit: EmitSpec,            // 命中后提取哪些对象、字段及范围
}
```

规则准备时编译为只读 WatchPlan：目标密集索引、阈值、所需数值依赖和输出字段。
worker 共享 WatchPlan；主实体、文本名称、动态闭包和完整设备 ECS 留在主 World。
worker 无需为了规则复制设备实体。规则与基准在本批次内固定，新配置在下一批生效。

同一目标的规则共享必要指标计算；多个命中需要相同输出时合并提取范围。全批没有
规则时只执行数值求解和完成计数。少量规则仅计算它们需要的指标；电流/加载率规则
仍需要计算对应支路电流，电压规则可直接读取已求得的电压。

### worker 内的两阶段后处理

```text
SolveBatch
  → EvaluateWatchPlan（批量计算必要指标、判断条件）
  → 本地 N1TriggerHit message
  → ExtractTriggeredPayload（按 EmitSpec 提取/计算指定输出）
  → 有效载荷非空才写外部结果 MPSC
```

N1TriggerHit 包含组内场景索引、case_id、退出设备标识、rule_id、目标索引和触发值。
提取系统运行期间，组内电压缓冲保持有效；外发 payload 在缓冲复用前成为独立所有的
数据或独占移交的输出缓冲。MPSC 收集者不再承担潮流数值后处理。

求解失败由状态规则判断。电压/潮流等数值规则只在可用的求解状态下运行，失败场景
继续计数并处理下一项。每项 N−1 是独立事件，不做跨场景时序边沿/滞回推断。

### 输出大小和回传背压

结果 MPSC 同样有界，独立收集者从 worker 启动时开始消费。命中率很高时，先把
当前组的命中按配置的 emit_bytes_max 分段发送；达到上限就发送当前段并复用输出
缓冲。单个大对象允许按固定字段/范围分段，保留 case_id、rule_id 和分段标识。
完成输出背压由结果队列显式承担。

结果存储只按真实触发量增长；长期运行可由收集者流式归档，省去 O(M) 的完整场景
结果保留。任务组上限、队列容量、worker 输出字节上限共同限制在途内存。

### 静默完成与终止协议

结果队列只有触发数据，因此完成判定独立于消息条数。worker 在组内所有场景的
规则判断、数据提取和必要发送完成后，将本组 processed/failed/emitted 计数合并
到自己的进度槽（按组发布）。空命中仍推进 processed。

worker 取不到新组且观察到 producer_done 后，完成自己的工作并以 Release 发布
退出标志。收集者在 Acquire 观察到所有 worker 退出后，再排空结果队列即可结束。
这保证最后一个输出的发送先于 worker 结束；join 后主系统读取最终进度并释放共享
资源。全批零命中也能正常结束，MPSC 完全没有业务消息。

DCPF 当前使用聚合 Ybus 非对角元素的模构造 B。DC patch 按“基准聚合元素”与
“退出后的聚合元素”之差计算，包含 Slack 边界 RHS 和变压器移相注入。用实际
`DcpfModel::from_ybus` 重建结果作对照，覆盖并联、变比/移相与 Slack 相邻设备。

新只读求解入口接收共享 CSC 和 J 结构。旧 Solve 的可变索引切片及旧 NR 中的
可变索引转换保持在旧入口，专用 N−1 系统直接使用只读结构接口，复用已核对的
数值运算逻辑。全部 worker 数值缓冲和 KLU Common/Numeric 相互独立。

## 空闲、结束与队列容量

主线程发完全部任务后，以 Release 设置 `producer_done`。worker 每次先 Acquire
读取该标志，再尝试取任务：取到任务组就计算完整组，空队列且看到结束标志就退出，其余情况
先短暂 yield、持续空闲后 sleep。主线程 join 全部 worker 后完成执行生命周期。

任务与结果队列容量均有界，按 worker 数和内存预算配置，独立于场景总数无限增长。
生产者与收集者分开推进；收集者按 worker 退出及排空协议完成，零触发仍可退出。

## 后处理与批量触发器的后续方向（本轮记录）

用户确认：保留已有高性能后处理及 AVX kernel 的复用方向。当前先完成真正的
N−1 场景任务；这一节作为后续设计记录，具体内核适配以本地代码和测量为准。

- 原始 ECS 实体身份作为外部主键，准备时映射到小型 SoA 的密集行号；保留实体
  身份到后处理字段、规则、输出范围的关联，worker 只共享必要数值与配置。
- 实体挂载的触发器可表示为函数入口加只读参数。批量接口读取一组指标，输出命中
  掩码；相同函数可分组执行，减少逐实体/逐场景的动态分派。
- 沿用原有后处理数值内核，优先核对和复用已有 AVX 路径。上层 batch 可动态选择
  4、8、16 等大小，仍受任务组硬上限及内存预算约束。
- 区分外层调度 batch、后处理场景 batch 与 SIMD kernel 的 lane 宽度。内核以
  lane tile 处理，一组可包含多个 tile；尾组使用有效 lane 掩码、尾部内核或
  标量收尾。无效 lane 排除在触发、输出和完成计数之外。
- 保持布尔命中掩码与当前场景退出掩码一致。触发为零时省去提取和 MPSC 写入；
  命中后按原实体身份提取配置指定的数据。
- SIMD 化与数据布局转换的收益在真正 N−1 基础路径正确之后测量，本轮未实现
  新 SoA、AVX 适配或批量触发器。

当前基础实现仍以重复 base 任务为队列入口。实际退出仅在测试中通过固定结构
参考数值回填验证。下一步优先把真实设备退出描述符、Ybus/B/RHS patch 和对应
