# RustPower 0.6.0

RustPower 0.6.0 introduces the experimental N-1 execution framework and optional CUDA/cuDSS acceleration while retaining a lightweight CPU-only default for ordinary Rust builds.

## Highlights

- Reusable prepared N-1 baselines with fixed bus partitions, shared symbolic analysis, private numerical workspaces, and bounded worker queues.
- Entity-based branch fault selections, topology pre-screening for slackless islands, numerical failure selections, and DC retry support.
- Status-only and detailed reports with NumPy event, violation, and branch-flow columns.
- Native FP64 Windows CUDA/cuDSS execution with batched Ybus outage patches, Jacobian assembly, Newton solves, and branch postprocessing.
- Hybrid CPU/GPU execution using a bounded CUDA-first queue with CPU overflow. Hybrid execution is an experimental scheduling option, not a universal performance guarantee.
- Python `backend="auto"`, `"cpu"`, `"cuda"`, and `"hybrid"` selection. Reports expose the actual backend in `summary["backend"]`.
- Runtime CUDA probing and dynamic native-library loading. Missing NVIDIA libraries or devices do not prevent Python import or CPU execution.

## Packaging

- Linux, Windows, and macOS wheels include the experimental CPU N-1 API with statically linked KLU.
- Windows wheels additionally include the small CUDA bridge and embedded PTX for compatible newer architectures.
- The heavyweight NVIDIA runtime is optional: install `pip install "rustpower[cuda]"` on Windows. Standard wheels do not bundle cuDSS, cuBLAS, or NVRTC libraries.
- Ordinary Cargo defaults remain CPU-only. Native CUDA builds require the explicit `experimental_n1_cuda` feature, Windows, MSVC, CUDA Toolkit, and cuDSS.

## Compatibility and limitations

The N-1 and CUDA APIs are experimental. CUDA and hybrid execution currently support `base-ac` initialization, Windows x64, and device 0. N-1 requires a fixed bus partition and therefore `qlim=False` during grid preparation. Existing CPU power-flow APIs and default Cargo features remain unchanged.

See `docs/n1_cuda.md` for installation, examples, native build configuration, and validation commands.
