# 初始PQ Nv=2的实际收益

9241：AMD内核约2.30→1.54ms，减少约33%。输入已准备好的排序入口约3.03→1.66ms，减少约45%；后一个数字包含图准备路径不同的收益，不能全归因于Nv=2。

这是已有、用户认可的PQ预合并Rust路径的性能诊断，没有设计新算法。两条路径都使用相同amd_2::<usize,true,false>、相同Control、编译优化和CPU0。没有改生产源码或默认配置。

## 实际路径和边界

标量：预先构造好的J CSC → order_unchecked → valid/AAT/amd_1 → amd_2(seed=None) → postorder → 两个排列。

Nv=2：预先分析好的YbusPattern → OrderingWorkspace::order_unchecked → QuotientGraph::initialize → amd_2(seed=Some(...)) → postorder → 两个标量排列。

YbusPattern分析和J组装都在测量区外。两条路径各自从已准备好的输入开始，每次新建工作数组。Nv=2的入口计时**不包含**Ybus合法性检查/列边界提取；若讨论首次完整求解，需要另把这些真实准备成本计入，本报告不提供完整NR数字。

为分清Nv=2内核收益和省去AAT等收益，另编译诊断版本，仅在amd_2开头与输出元组构建后读两次时钟。内核计时包含初始化、消元、后序和输出数组构造，结束于函数返还前；局部数组在返回时的自动析构不在内核小计内，入口时间包含相应清理。两次时钟只写在持久结果目录的amd-timed-source源码副本，不修改生产amd_2；正式耗时和火焰图使用未插桩的amd-original-source副本。

## Nv=2确实如何进入内核

生产原有代码：powerflow.rs:188准备权重对应的外部度，:223向amd_2传seed；amd_2.rs:118将PQ代表的Nv初始化为2，PV为1。同母线另一个标量变量为非主变量，最终仍输出完整标量排列。

9241：npq7796、npv1444。

|初始结构|标量|Nv=2预合并|
|---|---:|---:|
|有效初始代表数|17036|9240|
|初始邻接条目|112376|28404|
|最终标量排列长度|17036|17036|

预合并减少代表与邻接条目；内核仍保留17036维标量编号和若干工作数组，不能说所有数组都缩成9240，也不能把邻接减少75%当作总工作减少75%。

此预合并路径不承诺与普通标量AMD逐项相同。9241两排列有17005个位置不同，双方各自P/Pinv互逆、每次排序与各自参考一致。AMD估计L非对角非零从99171到98798（约-0.38%）；这是AMD Info估计，不是实测KLU L/U填充。39/118也通过各自排列逆置和重复一致性检查。算法本身未改，本次不新增数值求解验证或把排序降幅冒充NR降幅。
